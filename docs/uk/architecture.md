# Архітектура

🇬🇧 [English version](../architecture.md) — основна документація.

Ruinwood — це один процес Bun. Один цикл із фіксованою частотою оновлює спільну симуляцію, а кожен підключений клієнт має власну сесію, яка малює цю симуляцію ANSI-текстом.

```
            ┌────────────┐  тік (100 мс)   ┌──────────────────────────────┐
 telnet ───►│ GameServer │────────────────►│ Game                         │
 клієнти    │  (TCP)     │                 │  ├─ World (тайли, скрині)    │
            └─────┬──────┘                 │  ├─ MobManager (індекс + ШІ) │
                  │ одна на сокет          │  ├─ GroundItems              │
            ┌─────▼──────┐  читає стан     │  └─ Player × N               │
            │  Session   │◄────────────────┤                              │
            │  ├ Connection (telnet I/O)   └──────────────┬───────────────┘
            │  ├ Scene: Login | Play                      │ збереження
            │  └ Screen → diff рядків → сокет      ┌──────▼──────┐
            └────────────┘                         │ PlayerStore │
                                                   └─────────────┘
```

## Шари

| Шар        | Файли                    | Відповідальність |
|------------|--------------------------|------------------|
| `core`     | `Direction`, `random`    | Дрібні чисті утиліти. |
| `world`    | `World`, `tiles`, `noise`| Генерація острова, тайли, попередньо обчислені карти небезпеки й досяжності. |
| `game`     | `Game`, `Player`, `Mob`, `MobManager`, `Inventory`, `GroundItems`, `rules` | Симуляція. Нічого не знає про сокети й термінали. |
| `i18n`     | `Translator`, `Message`, `locales/*` | Переклади. |
| `net`      | `TelnetParser`, `KeyParser`, `Connection` | Протокол telnet, розбір клавіш, буферизований вивід. |
| `ui`       | `Session`, `Screen`, `scenes/*`, `widgets/*` | Стан клієнта й рендер. |
| `server`   | `GameServer`             | TCP-сервер, ігровий цикл, автозбереження, коректне вимкнення. |
| `storage`  | `PlayerStore`, `worldSeed` | Збереження в JSON. |

Залежності йдуть згори вниз: `ui` → `game` → `world` → `core`. Ігровий шар ніколи не імпортує `ui` чи `net`.

## Тік

Кожні 100 мс `GameServer` викликає `Game.update()`, а потім `Session.render()` для кожного клієнта:

1. Гравці: таймери відродження, відкладені кроки, регенерація.
2. `MobManager.update()`: ШІ мобів поруч із гравцями, зникнення далеких мобів, спавн на кільці навколо гравців.
3. Вибухи згасають. Раз на 10 тіків зникають старі предмети й наповнюються скрині.

Раз на 300 тіків (30 с) змінені дані гравців пишуться на диск. `PlayerStore` має прапорець змін, тож сервер без гравців диск не чіпає.

## Локалізація

Гра не зберігає готових рядків. Подія — це об'єкт `Message`, тобто ключ словника плюс параметри:

```ts
player.notify(msg("event.kill", { mob: msg(mob.kind.name), level: 3, xp: 12 }));
```

Параметрами можуть бути вкладені повідомлення або їхні списки, як-от лут зі скрині. Кожна сесія перекладає текст під час рендеру через `Translator.for(player.settings.locale)`. Тому:

- двоє гравців в одному бою бачать ту саму подію кожен своєю мовою;
- після зміни мови в налаштуваннях журнал подій одразу перекладається повністю.

`locales/en.ts` — еталонний словник. Інші мови мають тип `Dictionary`, тож пропущений ключ дає помилку компіляції, а тест перевіряє, що плейсхолдери збігаються.

## Рендер

- `Screen` — буфер клітинок, який використовується повторно: символ, колір тексту, колір фону, жирність. Пам'ять виділяється заново лише при зміні розміру вікна.
- `Screen.line(y)` кодує рядок в ANSI й додає коди кольору лише там, де атрибути змінюються.
- `Session` пам'ятає рядки попереднього кадру й надсилає лише змінені. Коли камера стоїть, кадр часто займає кілька рядків.
- `MapView` малює рельєф прямо з масиву тайлів, а потім накладає сутності: скрині, предмети, мобів, гравців. Раніше для кожної з ~3000 видимих клітинок робилося чотири пошуки в хеш-таблицях.
- `LogView` кешує перекладені й перенесені рядки журналу, поки не зміняться журнал, мова чи розмір.
- `Connection` тримає ненадісланий вивід списком шматків. Поки клієнт не встигає, `render()` пропускає кадри, а клієнта, що відстав понад 256 КБ, від'єднує.

## Моби

`MobManager` тримає поруч із множиною мобів індекс `Map<ключ клітинки, Mob>`. Завдяки цьому:

- перевірка зіткнень і пошук моба в клітинці — O(1);
- вибух бомби перевіряє 25 клітинок своєї зони, а не всіх мобів.

Список мобів, які можуть з'явитися на певному тайлі за певної небезпеки, обчислюється один раз і кешується. Рівень небезпеки обчислено заздалегідь, а відстань до табору в гарячих місцях рахується через квадрат відстані без `Math.hypot`.

## Сесії та сцени

`Session` показує одну сцену за раз:

- `LoginScene`: введення імені й перемикання мови до входу (Tab).
- `PlayScene`: сама гра з режимами `play`, `chat`, `help` і `settings`.

Клавіші перетворюються на дії (`Action`) в `ui/input.ts`. Ті самі фізичні клавіші працюють на латинській і українській розкладках. Сцени спілкуються з сесією лише через невеликий інтерфейс `SceneHost`.
